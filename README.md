# 阴阳师 · 御魂评分器（YYS Soul Scorer）

对着游戏截图，自动读出御魂的**套装 / 号位 / 主属性 / 副属性 / 固有属性 / 本次强化次数**，
按自定义方案给出**分数**和**留·观察·弃**的建议。

全程只做「看屏幕 + 算分数」——不读取游戏内存、不注入、不自动点击，鼠标键盘始终归你。

## 功能

- **两种界面都认**：御魂批量强化的结果页（一屏 N 张卡）、以及仓库/御魂列表右侧弹出的**详情面板**（只识别选中的那一件）。
- **属性全读**：主属性、副属性、固有属性，以及每条属性「旧值 → 最终值」的变化。
- **强化次数**：读卡片右侧（批量页）或属性值右侧（详情页）的徽章，知道这 5 次强化分别喂给了谁。
- **套装识别**：详情页直接读面板文字；批量页用卡片头部圆形图标做模板匹配（70 套图标模板）。
- **号位判定**：优先读图标角标 / 「壹号位」文本，读不到就按主属性推断，并在结果里标明是推断。
- **评分与建议**：按 `rules/中练度标准.yysrule.json` 匹配方案，给出分数和留 / 观察 / 弃。
- **三种出口**：图形界面看结果、命令行打印表格、导出 JSON / CSV / 标注图。
- **分辨率自适应**：所有坐标比例化，换分辨率不用改代码。

## 支持哪些界面

| 界面 | 说明 | 套装来源 | 号位来源 | 强化次数 |
| --- | --- | --- | --- | --- |
| 御魂详情面板 | 仓库 / 列表右侧弹出，显示选中的一件 | 面板文字 | 「壹号位」文本 | 属性值右侧徽章 |
| 批量强化结果页 | 一屏多张卡片 | 卡片头部图标 | 图标角标 → 主属性推断 | 卡片右侧徽章 |
| 单个御魂卡片 | 上面只剩一张卡时的退化情况 | 卡片头部图标 | 图标角标 → 主属性推断 | 卡片右侧徽章 |
| 单个面板（无卡片） | 检测不到卡片网格时的兜底 | 左上角区域搜图标 | 主属性推断 | 读不到 |

不支持：式神录 / 御魂强化前的选择界面等其它页面——那里没有可读的属性面板。

## 工作原理

一条链路，命令行和图形界面共用（[src/pipeline.py](src/pipeline.py)）：

```
抓窗口客户区 → 判断是哪种界面
                ├─ 详情页：浅蓝连通域定位面板 → 整块 OCR → 按文本框 y 归行
                └─ 批量页：投影法切卡片网格 → 逐卡切行
              → 逐行 OCR（放大后识别）
              → 解析「属性名 / 旧值 / 最终值」
              → 读强化次数徽章
              → 识别套装、判定号位
              → 匹配方案并评分
              → 打印 / 展示 / 导出
```

几个值得说的点：

- **怎么区分两种界面**：详情面板是一大块浅蓝底色，连通域面积占客户区约 14%；批量页里最大的一块只有 0.2%。用这个比例就能干净地判断，且批量页几乎不为此多花时间。
- **批量页切卡片**：面板位置相对固定，用比例 ROI 粗定位，再做行/列投影找峰值，自动分出 N 列 × M 行的卡片网格——卡片数量变化不用改坐标。
- **详情页为什么不能投影切行**：面板底色灰度 173~192，白色文字对比度太低，行投影切不出行。改成整块 OCR 一次，再按每个文本框的中心 y 归行。
- **强化次数徽章**：数字是纯白、很小（约 6×8 px），检测器经常漏。做法是先按亮度找数字连通域，按位置就近归到某一行，再贴着数字（批量页）或贴着深色圆盘（详情页）裁剪、放大 8 倍后只跑识别不跑检测。
- **套装图标匹配**：游戏会把同一套美术按御魂状态重新染色，所以只比灰度结构不比颜色；除了绝对相似度还要看与第二名的差距，两者都不够就返回 None，交给上层走「乐观上界」。
- **数值容错**：OCR 会把小数点读成全角或逗号、把双箭头 `»` 读成 `>` 或丢掉，所以解析按「已知属性名最长前缀匹配 + 抓数字（第一个是旧值、最后一个是最终值）」，不依赖分隔符。

## 安装

```powershell
git clone https://github.com/<你的用户名>/yys-soul-scorer.git
cd yys-soul-scorer

# 建虚拟环境（Python 3.10+）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

首次运行会下载 RapidOCR 的 PP-OCRv4 模型（约十几 MB），之后离线可用。

## 使用

### 图形界面

```powershell
.\.venv\Scripts\python.exe tools\gui.py
```

1. 在上方下拉框里选游戏窗口（点「刷新」重新扫描）。
2. 在游戏里切到御魂详情页或批量强化结果页。
3. 点「开始分析」。左边是截图（方框可点选），右上列表给出每件御魂的套装 / 号位 / 主属性 / 分数 / 建议，右下是属性明细和评分依据。
4. 需要留档就点「保存标注图 / 导出 JSON / 导出 CSV」。

不想开游戏也可以用「打开截图…」直接读一张图片。

### 命令行

```powershell
# 按标题关键字找窗口
.\.venv\Scripts\python.exe tools\read_panel.py --match 阴阳师

# 直接给窗口句柄
.\.venv\Scripts\python.exe tools\read_panel.py --hwnd 0x00091822

# 离线读一张截图，同时导出 JSON / CSV
.\.venv\Scripts\python.exe tools\read_panel.py --image samples\batch_6cards.png --json out.json --csv out.csv
```

| 参数 | 说明 |
| --- | --- |
| `--hwnd` | 窗口句柄，支持 `0x` 前缀 |
| `--match` | 按窗口标题关键字匹配（多个匹配时取面积最大的） |
| `--image` | 离线模式，直接读一张截图 |
| `--threshold` | 文字亮度阈值，默认 100 |
| `--scale` | 识别前放大倍数，默认 2 |
| `--json` / `--csv` | 结果导出路径 |
| `--no-save` | 不写调试图 `output/panel_read/annotated.png` |

## 评分规则

规则文件在 [`rules/中练度标准.yysrule.json`](rules/中练度标准.yysrule.json)（28 条方案），公式：

```
分数 = Σ 命中的核心属性 × (10 + 强化次数 × 10)
     + Σ 命中的一般属性 × (5  + 强化次数 × 5)
```

- 「命中」逐条计算：副属性和固有属性各算一条，同名属性可以叠加；**主属性不参与计分**。
- **方案匹配只看四项**：星级、号位、号位主属性配对、套装。等级、初始腿数、必备副属性不参与（这和评分公式的来源保持一致）。
- 留 / 观察 / 弃直接取命中方案自己的阈值。
- **套装没识别出来时**：取所有套装方案里分数最高的那个，结果里标 `套装未识别 · 乐观上界` 并列出备选方案——也就是说这个分数是上界，别当真。

换方案只要改 `rules/` 下的 JSON。

## 目录结构

```
YYS/
├─ src/                      识别核心（图形界面和命令行共用）
│  ├─ win_capture.py         窗口枚举 + 5 种截图后端
│  ├─ panel.py               批量页卡片 / 行定位（投影法）
│  ├─ detail.py              详情面板定位 + 整块 OCR 归行
│  ├─ ocr.py                 RapidOCR 封装（行识别 / 整块识别 / 标注图）
│  ├─ parse.py               行文本 → 属性名 + 旧值 + 最终值
│  ├─ badge.py               读「本次强化了几次」的徽章
│  ├─ seticon.py             套装图标模板匹配 + 号位角标
│  ├─ score.py               评分与方案匹配
│  └─ pipeline.py            串起整条链路，返回结构化报告
├─ tools/
│  ├─ gui.py                 图形界面
│  ├─ read_panel.py          命令行入口
│  └─ ...                    标定 / 诊断小工具（见下）
├─ tests/                    回归测试
├─ rules/                    评分方案
├─ data/soul_icons/          70 个套装图标模板（文件名 = 套装名）
├─ samples/                  示例截图
└─ requirements.txt
```

`output/` 是运行产物目录（截图、标注图、导出的 JSON / CSV），已在 `.gitignore` 里。

## 回归测试

```powershell
.\.venv\Scripts\python.exe tests\test_parse.py    # 属性行解析
.\.venv\Scripts\python.exe tests\test_score.py    # 评分与方案匹配
```

`test_score.py` 会拿平安志（yys-analysis）自己算出的评分记录当标准答案逐条比对。本机实测 **9013 条全部一致**（分数 100%、命中方案 100%）。找不到那个数据库时（比如换了机器）会自动跳过比对，只跑不依赖数据库的纯逻辑检查。

底图级别的回归就是直接跑 `samples/` 里的截图，看输出有没有变化：

```powershell
.\.venv\Scripts\python.exe tools\read_panel.py --image samples\batch_6cards.png --no-save
.\.venv\Scripts\python.exe tools\read_panel.py --image samples\batch_6cards_emulator.png --no-save
```

第二条（模拟器 1136x640）是给行投影边界 bug 留的哨兵——最右列的亮竖边框一压到列边界上，右下两张卡的速度行会整行丢失，这条一跑就能看出来。

## 开发与标定工具

改识别逻辑（尤其是换分辨率、换游戏版本）时这些工具有用：

| 工具 | 用途 |
| --- | --- |
| `tools/test_capture.py` | 逐个试 5 种截图后端，找出这台机器上能截到 DX 窗口的那个 |
| `tools/analyze_grid.py` | 打印行/列投影，标定批量页的卡片网格 |
| `tools/profile_panel.py` | 面板 ROI 内逐行亮像素统计，标定阈值 |
| `tools/profile_column.py` | 某一列的逐行亮度，区分边框行和文字行 |
| `tools/probe_panel.py` | 切开每一行并导出裁剪图，人工核对切分 |
| `tools/ocr_panel.py` | 只跑「切行 + OCR」，导出标注图 |
| `tools/snip.py` / `tools/snip_cards.py` | 从窗口裁指定矩形 / 裁每张卡片存图 |
| `tools/debug_cards.py` | 逐卡打印行框坐标与 OCR 原文 |
| `tools/test_scale.py` | 缩放当前帧，验证检测环节的分辨率自适应 |

## 常见问题

**截出来是黑屏？**
游戏是 DX 渲染，某些后端截不到。跑 `tools/test_capture.py --match 阴阳师` 看哪个后端能出图，或把游戏切到前台再截。

**识别不准 / 漏行？**
先把 `output/panel_read/annotated.png`（标注图）和 `tools/ocr_panel.py` 的结果对一下，判断是切行错了还是 OCR 错了。切行问题用 `profile_panel.py` / `analyze_grid.py` 重新标定；OCR 问题先试 `--scale 3`。

**换分辨率还能用吗？**
能。所有坐标都按客户区高度相对基准 790 换算，像素阈值走同一个比例。

**一定要开游戏窗口吗？**
不用，`--image` 或界面的「打开截图…」都能离线跑。

**为什么分数是「乐观上界」？**
套装图标没认出来。此时评分取所有套装方案里的最高分，所以只会偏高，不会偏低。改用详情页识别（直接读面板文字）最稳。
